# EviTrack – FRONTEND ARCHITECTURE (Vite + React + TypeScript)

> The previous `docs/FRONTEND.md` (Django-template page inventory) must be moved to `docs/archive/FRONTEND_LEGACY_INVENTORY.md` before this file is added.
> This file says **how to build** the SPA. What it must look like: `UI_SPEC.md`. How it behaves: `UX.md`.

## 1. Stack (decided; do not swap)
| Concern | Choice | Why |
|---|---|---|
| Build | **Vite 5** | Fast dev, simple config |
| UI | **React 18 + TypeScript (strict)** | Typed, widely supported |
| Routing | **React Router 6** (data router, lazy routes) | Code splitting, guards |
| Server state | **TanStack Query 5** | Caching, retries, invalidation, loading/error states |
| Client state | React Context for auth, theme, toasts; `useState` locally. No Redux | Keep it small |
| Styling | **Tailwind CSS 3** with design tokens as CSS variables (`styles/tokens.css`), plus a small `print.css` | Fast, consistent, dark mode via class |
| Primitives | **Radix UI** (Dialog, DropdownMenu, Tabs, Tooltip, Popover, Toast, Select) wrapped in our own `components/ui` | Accessible by default |
| Icons | `lucide-react` | Consistent line icons |
| Forms | `react-hook-form` + `zod` | Inline validation matching API errors |
| Charts | `chart.js` + `react-chartjs-2` | As in the spec |
| Calendar | `@fullcalendar/react` (+ daygrid, timegrid, list, interaction) | As in the spec |
| Fonts | `@fontsource/inter`, `@fontsource-variable/source-serif-4`, `@fontsource/jetbrains-mono` (self-hosted, CSP friendly) | No external requests |
| API types | `openapi-typescript` generated from the backend OpenAPI schema | One source of truth |
| Tests | **Vitest + React Testing Library**, **Playwright** for e2e, `axe-core` checks in e2e | Unit + flow + a11y |
| Lint/format | ESLint (react-hooks, jsx-a11y), Prettier | Quality |
Keep dependencies to this list. Anything else needs a one-line justification in `PROGRESS.md`.

## 3. Routing
- Routes as listed in `UX.md` §2. All feature routes are lazy-loaded (`lazy: () => import(...)`).
- `PublicLayout` wraps landing, `AuthLayout` wraps login/OTP/register, `AppShell` wraps everything after sign-in.
- Guards: `RequireAuth` (redirect to `/login?next=`), `RequireRole(roles)` (403 page if the role lacks access). Role helpers live in `lib/roles.ts` and mirror `SPEC.md` §1.
- Route errors use an `errorElement` that shows the 500 page; unknown paths show 404.

## 4. API layer
- `api/client.ts` wraps `fetch`: base `/api/v1`, `credentials: "include"`, sends `X-CSRFToken` from the `csrftoken` cookie on unsafe methods, JSON in/out, multipart for uploads.
- Errors normalised to `ApiError { status, code, message, fields?, retryAfter? }`. 401 → clear session and navigate to `/session-expired`; 403/404/429 surfaced per `UX.md` §6.
- Uploads use `XMLHttpRequest` (or fetch + progress polyfill) to report per-file progress.
- Query keys come from `api/keys.ts`; mutations invalidate precisely the keys they affect.
- Types: `npm run api:types` runs `openapi-typescript http://localhost:8000/api/schema/ -o src/api/schema.gen.ts`. Run it after every backend contract change; never hand-write response types that the schema already provides.
- Dev: Vite proxies `/api` and `/media-protected` to `http://localhost:8000`. Production: nginx serves `frontend/dist` and proxies `/api`.

## 5. Auth and session
- `AuthProvider` loads `GET /auth/me` on startup (`null` when signed out) and exposes `{ user, role, can(permission), signOut }`.
- Login is a small state machine: `credentials → otp → (totp) → done`; each step maps to a route and survives refresh via server-side challenge state (not localStorage).
- `SessionTimeout` uses `useInactivity` (13 min warning, 15 min end), calls `POST /auth/session/ping` on "Stay signed in".
- Never store tokens or user secrets in localStorage. Theme preference is saved via the API and cached in a `class` on `<html>` before first paint (inline-free: use a tiny blocking script file allowed by CSP, or read a cookie server-side).

## 6. Styling and tokens
- `styles/tokens.css` defines every colour/spacing/radius/shadow variable from `UI_SPEC.md` §0 for `:root` and `.dark`. `tailwind.config.ts` maps utilities to those variables, so components use semantic classes (`bg-surface`, `text-muted`, `border-border`, `bg-primary`).
- Dark mode is class-based (`html.dark`). Charts, FullCalendar and PDF previews read tokens at runtime.
- No inline styles except dynamic values. No `!important`. Respect `prefers-reduced-motion`.

## 7. Component rules
- Every `components/ui` component: typed props, forwardRef where relevant, keyboard and ARIA support, all states (hover, focus-visible, disabled, loading, error), dark-mode safe, a Vitest test for behaviour that is not trivial.
- Feature components compose `ui` components; no raw Radix imports outside `components/ui`.
- Pages are thin: fetch with hooks, render states (`isPending` → skeleton, `isError` → ErrorState, empty → EmptyState), compose components.
- Every list/detail page implements loading, empty, error and success states (see `UX.md` §5–6).
- Role-aware rendering through `can()`; hidden, not disabled, per `UX.md` §4.

## 8. Forms
`react-hook-form` + `zod` schema per form in the feature's `schemas.ts`. On API 400, call `setError` for each key in `fields`. Show a top summary when more than two errors. Disable submit while pending. Warn on unsaved changes with `useBlocker`.

## 9. Performance and quality bars
- Route-level splitting; FullCalendar and Chart.js only in their routes.
- Lighthouse (desktop, seed data): Performance ≥ 85, Accessibility ≥ 95, Best Practices ≥ 95.
- No console errors or warnings in e2e runs. `tsc --noEmit`, ESLint and Vitest must pass before every push.
- Bundle: initial JS under ~250 KB gzip.

## 10. Testing
- **Vitest + RTL:** ui components, forms (validation, API error mapping), role helpers, hooks.
- **Playwright:** one spec per journey (J1–J8) plus a per-page smoke crawl; run at 1440×900 and 390×844; log in as the right demo role; screenshots to `docs/screenshots/<slice>/`; `@axe-core/playwright` check on each main page (no serious/critical violations).
- Dev-only OTP access for e2e: the test environment uses a file-based email backend (directory set by env) that the Playwright helper reads. This must be impossible in production settings.

## 11. Build and deploy
- `npm run dev` (5173), `npm run build` → `frontend/dist`, `npm run preview`, `npm run test`, `npm run e2e`, `npm run lint`, `npm run api:types`.
- Docker: multi-stage build (node → static files) copied into the nginx image; nginx serves SPA with `try_files $uri /index.html`, proxies `/api` to gunicorn, keeps `/protected-evidence/` internal.
- CSP must allow only self-hosted scripts/fonts/styles; no inline scripts.

## 12. Cutover plan (slice S12)
Until cutover Django keeps serving its template UI. At cutover: Django (or nginx) serves the SPA `index.html` for every path except `/api`, `/admin`, `/static`, `/media-protected`; legacy template views, URLs and templates are removed or moved to `/legacy/` behind DEBUG; legacy tests are deleted only when the equivalent API and e2e tests exist.
